# 动作契约样例：应拒绝派发

这是对 V0.5 附录 A 的公开简化设计，非天猫 API、非生产配置、非已实现的校验器。对象均为虚构；填写字段不产生授权，也不证明平台能力。下面状态必须被执行器拒绝，不能仅改一个布尔值就绕过审批。

| 字段组 | 样例状态及要求 |
| --- | --- |
| 环境与模式 | environment=design_example；mode=draft_only；external_write_enabled=false |
| 身份 | tenant/store/task/change/action 均为 demo 标识；attempt 尚未创建 |
| 动作 | 商品内容编辑；只允许主图引用与详情内容；价格、库存、SKU 身份、上下架禁止夹带 |
| 意图绑定 | 提案版本、对象清单、语义载荷摘要、最终素材版本及到期时间必须固定；目前均未齐备 |
| 当前事实 | 决策基线、派发前观察、商品事实、规则和数据时点均缺失 |
| 授权 | approval_id=null；preauthorization_policy_ref=null；binding_status=NOT_AUTHORIZED |
| 证据 | 清单固定版本和留存政策缺失；gaps=授权缺失、事实缺失、内容缺失 |
| 连接器 | capability=UNKNOWN；图片上传副作用=UNKNOWN |
| 执行 | status=DRAFT；automatic_write_retry=false；禁止无持久意图派发 |
| 核验 | 实际结果为空；状态未核验；动作归属未知；展示未核验 |
| 恢复 | 先重验当前状态；补偿新建动作；不恢复旧库存/预算，不覆盖后续人工变化 |
| 学习 | 结果尚未评价；不自动发布策略 |

## 派发前必需检查

有效授权明确绑定店铺、动作、对象范围、提案版本、载荷摘要、最终素材及有效窗。动作意图、批准差异、当前前置条件、内容固定版本和可靠证据清单均应落账。执行时再次检查停止状态、撤权、过期和冲突。

本样例的预期结果：REJECT，不生成外部写请求；拒绝原因可查。实际开发应通过类型、状态机、授权校验、持久化和连接器测试实现此判据，文档本身不执行它。

## 派发后需追加

每次 attempt、响应或明确 UNKNOWN、平台观察或证据缺口、关联广告检查、恢复/接管及残余影响。不能用期待值填充实际结果。

如果真实接口分成上传、绑定和提交详情，需独立子动作及尝试；批量、定时、价格、库存、状态和广告使用各自契约，不直接复制内容编辑白名单。
