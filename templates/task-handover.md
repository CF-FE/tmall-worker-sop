# 单任务移交与受控档案包

依据 V0.5 附录 B 整理的逻辑模板，不是真实经营档案。正式数据进入受控系统，不进入公开仓库。平常使用稳定引用和固定版本，不要求每个动作复制整个目录。

## 包内逻辑分区

| 分区 | 内容 |
| --- | --- |
| manifest.json | 清单版本、文件摘要、来源、范围、权限与缺口 |
| summary.md | 人可读经过，各项结论指向证据 |
| decisions/ | 提案、依据、备选方案、拒绝或不调整理由 |
| approvals/ | 批准范围、预授权及撤回，不含认证凭据 |
| actions.jsonl | 逐对象业务意图与动作状态 |
| attempts.jsonl | 请求尝试、脱敏回执及错误 |
| events.jsonl | 状态变化、迟到证据、更正和接管 |
| snapshots/ | 决策原状态、执行前状态与实际观察 |
| assets/ | 仅限获准导出的素材实体及详情结构 |
| verifications/ | 请求、平台、展示的核验时间与范围 |
| recovery/ | 补偿/修复、人工移交、未决风险和残余影响 |
| evaluations/ | 暂估/成熟结果、对照、干扰及更正版本 |
| coverage.json | 来源覆盖起点、水位、空窗、归属和证据可用性 |

## 清单与移交验收

- 任务、对象、版本、导出者、导出时间、接收者和允许用途明确。
- 清单记载脱敏策略、准许导出的字段/文件以及各项完整性校验结果。
- 缺文件不能静默忽略：分别说明无权导出、已到期、未知、损坏或尚未取得。
- 被移交者明确接受未决事项、期限、责任及接管范围；关闭任务不抹去未知请求或持续广告消耗。
- 验证必要素材可读、引用有效、权限正确；含加密数据时在获准范围验证解密与恢复。
- 后续更正或迟到回执产生补充版本，不倒写原来的批准与执行事实。
- 不盲目打包客户明细、凭据及全部模型输入；仅导出接收方获准且用途必需的信息。
- 记录到期、销毁及备份传播要求；证据被合法处置后明确重建限制。

这是按需审阅、交接或事故调查的导出结构，不能替代数据库里的动作/授权账本，也不表示已有完整运营档案系统。
