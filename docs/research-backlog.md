# 待验证问题与推进顺序

状态：公开研究待办，不表示已获生产权限。

## P0：实施前必须澄清

- 目标类目、发布体系、合法货源与素材范围。
- 实际商品、SKU、广告对象标识和权威数据源。
- 商品字段、SKU 状态、图文发布与回读权限。
- 目标广告模式、可控参数、原生预算限制和停投生效延迟。
- 成本、退款、税费、库存、锁库、归因窗口和业务日口径。
- 人工/ERP/其他服务商并发控制，以及谁负责紧急接管。
- 写入超时的查询依据、幂等范围与期限、部分失败行为。
- 素材与证据保留政策、恢复目标和模型数据处理范围。

## 建议推进阶段

1. 完成逐动作能力矩阵，写明已确认、未确认、不可用和需要人工的项目。
2. 用虚构数据跑选品、商品编辑和一种广告动作的影子闭环，不连接生产写。
3. 在具体授权对象上验证商品编辑/状态与广告写入，逐项回读，不扩大批量。
4. 故障注入、外部变更核对、档案抽检和备份恢复。
5. 只有证据支持后，才讨论有界自主范围及策略晋升。

## 研究扩展清单

- 当前天猫类目规则和商品发布要求：需官方当前条款与目标商品核验。
- 阿里妈妈实际账户产品及开放接口：需要账户能力盘点，不能用其他平台术语替代。
- 两条视频的作者观点：独立核查规则与效果，保留适用平台及历史时间。
- 选品：补充需求样本、供给、资质、毛利、售后、季节性和实验设计。
- 数据治理：指标字典、来源水位、空窗、版本、更正和授权导出。
- 经济评价：对齐退款成熟度和费用归集；增量实验可行性另评估。

## 关闭标准

研究项只有在具备来源/时间/范围、目标店铺验证记录及明确结论时才关闭。官方文档核查、模拟测试、真实调用和经营效果分别登记，不能用一个“完成”复选框混合。
