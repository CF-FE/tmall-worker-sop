# 项目基线与版本关系

## 必须解决的业务问题

选什么商品、为何可投、如何准备商品表达、如何设置预算、何时保持或调整、如何确认变更生效、净贡献如何、哪些经验值得保留。

首期限定天猫单店单品类和已授权对象。目标包括实际商品建档、整商品和单 SKU 状态管理、标题属性与图文商详编辑、受控广告动作。只读和提案是过渡阶段，不能作为最终执行能力的替代。

采购仓储、客服赔付、完整 CRM、直播/达人代运营及多平台经营不是首期主体；它们的约束可以影响商品准入。抖店教程只用于比较，不扩大天猫实施范围。

## 能力分组

| 领域 | 继承模块编号 | 首要产物 |
| --- | --- | --- |
| 商品经营与经济模型 | SE01—SE02 | 商品池、成本/退款口径、可接受风险 |
| 搜索表达与素材 | SE03—SE04 | 有事实和许可支持的标题、图片、商详版本 |
| 流量诊断与计划 | SE05—SE09 | 诊断、模式选择、对象和参数提案 |
| 消耗与复盘 | SE10—SE12 | 累计风险、异常处置、成熟评价、候选经验 |
| 商品执行 | SE13—SE16 | 建档、SKU、图文发布、展示核验和广告联动 |

八项共享能力分别承担数据质量、主编排、授权执行、效果评价、策略治理、模型适配、证据查询、外部核对与恢复。它们是责任边界，不是八个可自由操作后台的独立 Agent。

## 设计取舍

1. 采用单一持久化主编排，避免多个组件重复恢复同一任务。
2. 所有生产写入经过统一授权执行入口，先持久保存意图和批准版本，再发送。
3. 关系型账本保存动作事实；版本仓保存必要素材和证据；检索和监控只是可重建视图。
4. 外部真实状态、系统动作归属和经营因果分别描述。
5. 超时先核对，部分成功逐对象处理；恢复前重读当前状态。
6. 学习产生候选经验，不能自行扩权、改预算或发布生产策略。

这是一组待实现的架构约束，不证明任何组件已部署。具体框架、数据库、对象存储及模型供应商尚需结合环境和验证选择。
