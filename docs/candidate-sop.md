# 候选业务 SOP

状态：设计提案，未在目标店铺执行。所有具体阈值、周期、额度、字段和负责人须现场确认。

## SOP-01：选品与投前准入

输入：需求证据、商品真实规格、货源/许可、成本、售后和退款、履约能力、库存时点、现有流量及转化。

步骤：
1. 按同一类目、价格带、规格及时间窗比较需求，不把平台推荐或单个热销截图当需求结论。
2. 检查供货稳定性、质量、知识产权、允许销售范围和可兑现的承诺。
3. 计算净销售、广告前贡献与可接受探索成本，缺少成本或成熟退款数据时标记未知。
4. 检查标题、属性、SKU、图片、商详、售价和可售状态是否一致。
5. 输出可投、限额试验、先修商品或补证，并记录有效期、退出条件和不调整的理由。

不做：照搬他店素材、保证爆款、用缺失值表示零退款、未经授权批量铺货。

## SOP-02：商品图文及 SKU 变更

输入：精确商品/SKU 身份、现有内容、适用编辑规则、获准素材、允许字段和批准版本。

流程：读取当前规则及状态 → 制作候选内容 → 对照商品事实与素材许可 → 形成逐字段差异和预览 → 批准最终版本 → 保存执行前凭证 → 分步发布 → 分层核验。

核验分为请求受理、后台实际字段、限定情境的展示/可售。主图成功而详情未知必须分别记录，不整包重发。图片上传如果直接修改在线商品，本身就是生产写动作。价格、库存、规格结构及类目变化不能夹带在“改图文”中。

单 SKU 停售不等于整商品下架，不能用零库存、异常价格或删除规格替代未授权动作。恢复销售不自动恢复旧库存或已由人工暂停的广告。

## SOP-03：流量与承接诊断

按同一口径观察曝光 → 点击 → 访问 → 支付，同时查看退款、履约、库存和利润。点击次数、访客人数、订单量不是同一计数单位，不直接拼接不兼容分母。

- 曝光不足：检查商品准入、场景、需求和实际投放资格，不直接得出“加预算”。
- 点击不足：检查标题/图片与需求是否匹配，形成可验证假设。
- 有访问无成交：先检查可售、价格、规格、详情、服务承诺和样本成熟度。
- 成交增加但贡献恶化：核对广告费用、退款、折扣和成本，不能以 GMV 单独宣布成功。

上述是分析路线，不是平台算法定律；关联趋势不能证明某项修改造成结果。

## SOP-04：受控投放

先选本账户真实支持的一种投放模式。登记对象、允许动作、预算上限、累计占用、在途未知请求、观察窗及接管人。生成具体差异，批准后落账并执行，回读参数和状态，持续观察消耗。

预算是上限而非花完的目标。程序校验金额和累计限额，模型不能替代额度控制。降低预算不追回已发生消耗，停止 Agent 不等于停止广告。

## SOP-05：效果复盘与经验管理

采用项目定义且保持对象与窗口一致：
- 净销售 R：按财务确认口径调整退款后的收入。
- 广告前贡献 M = R - 商品成本 - 非广告可变费用。
- 广告后贡献 = M - 归集广告费 A。
- 当 R、A 为正时，净销售 ROAS = R/A；当贡献率 m=M/R 为正时，静态保本 ROAS=1/m。

这些是核算关系，不是增量归因或公司净利润，且扩大预算可能改变贡献率。平台归因、经营核算和因果实验三种结果分开。记录同期改价、改图、活动、库存和投放变化等干扰。

候选经验包含条件、动作、观察窗、结果、反例、证据强度和失效条件。经过复核和受控验证后才发布为策略，支持撤回。失败、无效和保持不动的案例同样保存。
