# 综合设计补充：工作流、档案与交付

整理日期：2026-11-08。依据 V0.5 全文重新组织的公开原创说明。下列名称、字段及门槛是项目设计，尚未实现；不是平台原生 API 或现有运行记录。

## 八条业务链路

| 编号 | 目标与最小产物 | 必须保留的分支 |
| --- | --- | --- |
| SF01 | 核对商品事实、经济模型、供给与表达，形成有时效的投前准入结论 | 缺证、先修商品、限额探索、暂不投 |
| SF02 | 在实际可用模式下形成计划及预算差异，批准、执行、核验 | 超时未知、创建重复风险、累计额度不够 |
| SF03 | 检查数据时效和风险，决定保持、调整或退出 | 不调整也记录理由；系统停止后平台可能仍消耗 |
| SF04 | 将流量问题与商品承接问题组成可检验假设 | 同期改价、改图、活动及库存造成的干扰 |
| SF05 | 用成熟结果与失败反例形成经验，验证后发布并监测 | 无效、无法归因、策略撤回及旧提案失效 |
| SF06 | 从产品事实到商品/规格、素材、批准发布和可售核验 | 创建不等于上架，上架不包含广告授权 |
| SF07 | 读取当前商品规则，编辑内容，批准最终差异并分步发布 | 图文部分成功、素材变化、展示滞后 |
| SF08 | 区分整商品与 SKU 的状态控制，并检查广告依赖 | 紧急停售、单规格影响、恢复销售不自动恢复广告 |

共享流程之一处理系统外变化：采集日志或状态 → 关联已知动作 → 无法归属时建立核对事项 → 控制冲突写入 → 留下证据缺口。快照只能证明观察差异，不能还原两次观察之间全部操作。

另一共享流程处理档案生命周期：按动作契约检查证据 → 补证或明确不可补 → 固定清单版本 → 权限化查询/导出 → 按已批准政策保留或处置。档案完整不代表业务成功，合法到期后也不能宣称仍能完整重建。

## 最小数据关系

| 设计实体 | 用途 |
| --- | --- |
| business_task | 经营目标、触发、范围、负责人及终结理由 |
| change_set | 一组相关变更及其提案版本 |
| action | 一个固定的业务意图、对象、授权和恢复类型 |
| attempt | 某次实际请求的发送、返回及错误 |
| audit_event | 状态演进、迟到证据、更正和接管事实 |
| evidence_object | 证据版本、来源、许可、摘要及可用性 |
| external_change_case | 未能匹配系统动作的外部变化及核对结果 |
| evaluation / lesson | 成熟度、干扰、反例、策略发布与撤回 |

任务到动作是一对多，动作到尝试也是一对多。批量请求还需关联每个子对象，不能仅保存父批次“成功”。外部 ID 无损保存；金额带币种和明确精度；环境、店铺与账号不能混用。

分开记录 baseline_before、pre_dispatch_observed、desired_after、observed_after，防止把期待值当真实结果。来源事实、人工事后申报和模型解释分层；状态是否符合、动作是否归属于本次请求、操作者是否可识别、授权证据是否完整分别标记。

时间至少区分源数据截至、采集、发生、观察、持久化和生效；无法确定则保留区间或空值。业务日需明确 Asia/Shanghai，存储时间可采用 UTC 并保留时区。

## 四个独立状态域

- 任务：接收、核验、分析、提案、待批准、执行、观察、关闭；另有暂停、阻塞、取消及升级。
- 动作：草稿、授权、意图落账、派发、等待、确认生效；另有未生效、未知、部分成功和冲突。
- 档案：开放、执行前就绪、执行后取证、封存；缺口、完整性异常与补充版本独立表达。
- 经营评价：未评价、观察、暂估、成熟、无法判定、已失效。

档案可完整记录失败，任务可移交人工后关闭，经营收益仍可能未成熟。三者不能互相替代。关闭风险任务需明确接收者、未决问题和期限。

## 模型、策略与数据治理

模型调用保存渠道、版本或别名、模板/工具版本、必要输入输出、成本和可核验理由摘要，不要求隐藏思维链。供应商回退不能改变动作身份或将私密档案发往未授权接收方；重新生成的图片或参数须成为新提案版本。

事实、事件、候选经验、生效策略和权限/代码分层治理。候选经验不得改执行代码或自动扩权。发布策略应有适用条件、失效期限、反例和撤回机制，撤回需作用于缓存和待执行提案。

关键凭证不能采样；普通调试遥测可以分层。留存期限、争议保留、删除传播、备份和解密恢复需明确，不能只检查文件存在。真实档案不放本公开仓库。

## 工作台与交付

工作台至少支持商品版本/差异、商品及计划队列、审批影响、操作时间线、未知状态恢复、经营评价。自然语言检索应只读且受权限约束，不能自行拼接生产写操作。

七类交付包：业务/财务数据基线；动作与来源能力表；状态/授权/执行底座；商品与广告纵向样本；证据查询与留存治理；模型及评价；测试和人员移交。每包需负责人、产物、验收证据和缺口。

验收指标同时覆盖前置凭证、证据完整、结果核验、外部来源覆盖、档案重建、恢复质量、净人工节省及经营质量。指标分母应独立可核对；未知分母不能报全量覆盖，零样本不能报满分。

## 复核补充：容易丢失的执行细节

本节再次对照 V0.5 §8.3、§8.5、§9.1—9.3、§12.3、§13.2 及附录 A/B；仍属设计要求，未实现或实测。

### 固定素材与商品版本

素材档案记录固定 asset_id/asset_version、输入版本、许可范围、工具及必要参数、文件格式/大小/摘要、批准和使用有效期、线上资源与 item/SKU/详情模块绑定。商品修订记录 listing_revision_id、结构化字段、模块次序、图片角色和 SKU 映射，以及适用规则、差异、预览、回执和核验。

不能仅存线上 URL，也不能让已批准动作引用随 latest 漂移的对象。按授权和留存政策保存必要文件实体，使用固定对象版本。平台转换、压缩图片后可与原文件字节不同，应核验线上资源对应及实际展示，不强求压缩图与原图哈希一致。共享素材清理需先检查跨商品、待发布任务及留存依赖。

### 定时任务不是延迟后必然补做

到执行时点重新检查授权、库存、商品状态和规则。若有效窗口已过，取消或提出新方案，不自动补发过期操作。不能把定时任务恢复或队列积压当作新的业务授权。

### 经营阶段、归因与三个时钟

成熟商品以约束下的贡献为目标；新品以有限探索成本获得有效验证；清仓围绕批准损益回收库存；获客则需要有证据的客户价值与回收期。总预算、底价、利润底线和可接受损失由经营负责人确定，不能因模型建议自动改变。

保留平台归因定义、归因窗口、更新时间与数据版本；多个计划可能归因同一销售，不得简单相加后声称已经去重。财务口径已扣除的优惠不能再次扣减；费用分摊存在估计时记录规则。

分别制定三个反馈节奏：
1. 执行状态检查：请求是否受理、实际状态及硬约束。
2. 经营调整观察：样本和试验是否成熟，是否需要改变策略。
3. 退款与费用成熟：何时能给出较可靠的贡献评价。

不能因短时未成交连续改动或加码，也不能用结果观察期拖延硬授权止损。风险估算需考虑消耗速率、数据/发现/处置/平台生效延迟及在途金额；边界不可信时不称为损失硬上限。

### 回放隔离与不可信内容

审计回放只读历史事实；历史重算不持有生产写凭据；生产续办需重验当前条件、授权和控制权。模型重跑得到的新内容不能冒充历史输出，补偿也不能抹去原有事件。

商详及证据预览应净化并隔离，不运行来源中的不可信脚本。日志结构字段由可信代码产生，外部文本按数据转义/编码，防止伪造事件类型、操作者或状态。导出内容也不作为权限指令。访问、导出、更正及处置自身需要记录。

## 验收指标的分子、分母与排除规则

根据 V0.5 §15.2 整理。以下是待实现的测量口径，非已经达到的结果。每次报告附对象范围、时间窗、契约版本和独立核对来源。

| 指标 | 分子与分母或计算方式 | 防止误报的要求 |
| --- | --- | --- |
| 系统内前置凭证覆盖 | 有有效持久凭证的系统内生产写尝试数 / 独立核对得到的系统内写尝试数 | 结合执行出口或模拟平台计数，不仅从账本自算；设计测试要求全覆盖 |
| 阶段证据完整率 | 到达该阶段且具备必需证据的对象数 / 到达该阶段的应检对象数 | 必需项由动作契约版本定义，不能把缺失自行改为不适用 |
| 结果核验覆盖 | 完成适用结果核验的动作数 / 已发送且超过合理核验等待期的动作数 | UNKNOWN/PARTIAL 不冒充核验成功；正常等待期内对象另列 |
| 外部事件接入覆盖 | 已接入事件数 / 独立来源能证明的应有事件数 | 无完整分母时不可计算，改报对象、来源健康、游标和空窗 |
| 外部变化归属确认率 | 归属具备证据的已发现变化数 / 全部已发现变化数 | 不证明发现了全部外部变化 |
| 档案可重建率 | 按指定对象和时点成功构建证据包的样本数 / 抽检样本数 | 按风险分层抽样；合法处置和历史缺口另列 |
| 恢复质量 | 演练后进入预先定义可接受状态的案例数 / 演练案例数 | 进程启动、覆盖人工新值不算成功恢复 |
| 净人工节省 | 原流程工时 - 审批、复核、异常、返工、维护工时 | 纳入新增归档和审核负担，记录基线与样本 |
| 经营质量 | 广告后贡献、阶段目标、库存/退款保护及实验结果分别报告 | 不强行合成一个比例；区分平台归因、经营核算与因果增量 |

分母为零报无样本/不适用，未知分母报不可计算。执行出口或原生审计自身有盲区时同时披露。零越权、零错误重复副作用和零绕过执行闸门是约定测试范围内的安全门槛，不是任何生产环境永不失败的保证。
