# 执行、安全与验收

状态：验收设计，所有用例均为待执行，非测试报告。

## 动作契约

每种操作登记对象/字段、前置证据、授权范围及到期、金额和频次限制、并发条件、幂等能力、回读方法、UNKNOWN 核对方法和恢复边界。未登记的操作不进入自主执行。

动作 identity、批准版本、实际尝试和证据不可混为聊天摘要。保存决策基线、派发前状态、期望结果和观察结果四份独立信息。发生时间、观察时间、记录时间、生效区间分别表达；未知不补造。

建议执行次序：最终证据保存与验证 → 精确授权 → 本地事务写入意图/额度/outbox → 派发前再验证 → 记录每次尝试 → 外部请求 → 状态核对 → 分层结果核验 → 追加效果评价。

同一意图重试保留 action_id，每次请求使用 attempt_id。outbox 不提供跨平台原子性；本地去重不等于平台幂等。返回成功、状态符合、本次动作归属确认必须分开。

## 失败处理

| 情况 | 预期处理 |
| --- | --- |
| 授权/动作账本不可写 | 阻止新的自动生产写 |
| 证据保存失败或批准文件变化 | 阻止依赖该证据的发布 |
| 请求超时、响应丢失、派发中崩溃 | UNKNOWN，先核对，不盲重发或释放风险额度 |
| 部分商品成功、部分未知 | 子动作分别核对，禁止整批重做 |
| 人工并发修改 | 检查控制权与当前字段，不以旧快照覆盖 |
| 只读/展示延迟 | 保留等待或证据缺口，不伪装成功 |
| 查询索引宕机 | 区别于账本丢失，显示延迟和积压 |
| 从旧备份恢复 | 先只读隔离，核对外部已发生动作，再放行 |
| 广告仍在消耗 | 按明确授权处置或人工接管，记录残余暴露 |

## 最小故障验收集

| ID | 故障注入 | 需要的证据 |
| --- | --- | --- |
| V01 | 落账/授权失败 | 外部副作用计数为零，阻塞原因可查 |
| V02 | 平台执行后响应丢失 | 核对原请求，没有错误重复副作用 |

| V07 | 批量部分成功 | 子对象状态、数量和证据一致 |
| V08 | SKU 与图片映射错位 | 发布前拦截；已生效时限范围修复 |
| V09 | 多计划累计超预算 | 累计约束阻断，未知占用保留 |
| V10 | 数据断流但广告运行 | 明确空窗、独立风险核对及接管 |
| V11 | 证据丢失/摘要不符 | 隔离并阻断无依据恢复 |
| V12 | 旧备份、旧 Worker 恢复 | 不重放未知外部写；过时代际拒绝派发 |
| V13 | 外部文本注入或跨店访问 | 不扩大权限，不泄露其他店铺数据 |
| V14 | 快照间变更后又恢复 | 如实显示检测盲区，不报全量覆盖 |

每条测试记录环境、动作版本、故障点、实际副作用、结果、缺口和审阅人。模拟通过不等于真实平台验证通过。

## 档案与公开边界

权威记录采用追加更正、版本化证据和受控访问。哈希不能证明最初内容真实，也不能抵御同权限同时篡改正文与摘要。留存期限和删除规则须单独制定，不承诺永久保存或绝对不可篡改。

公开库只放脱敏设计与摘要；真实执行档案进入有权限隔离的业务系统，包含必要事实而非无限复制客户明细。认证头、密钥、session、客户身份、订单详情、真实经营数据和商家后台截图不得加入公开仓库。

验收同时看实际业务执行、净人工节省、经营质量、错误副作用和证据质量。分母未知时覆盖率不可计算，分母为零不写 100%。
